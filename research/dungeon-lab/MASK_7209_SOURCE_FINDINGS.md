# 수라가면 (7209) — 필드 고유 드랍 원본 분석

## 원본 60014 정적 정보

원본 한국판 60014 `char_data`에 NPC 30681 **만호강**, 레벨 70,
`drop: [7209,1]` (수라가면)이 들어 있다. 이 배열의 뒤 숫자는
원본 드랍 가중치이다. 별도 100칸 확률 모델은 재현 후보이며,
게임 내 실측으로 네이티브 분기 검증 전까지 **1% 확정**으로 격상하지 않는다.

동일한 70레벨에 명시적인 원본 `drop` 배열이 있는 추가 NPC:

| NPC | 이름 | drop 배열 |
| --- | --- | --- |
| 30681 | 만호강 | `[7209,1]` |
| 32950 | 산적 | `[3031,1]` |
| 34461 | 설랑 | `[[3081,30],[3086,50],[3917,20]]` |

이는 **원본 설정 내 명시적인 70레벨 drop 배열의 전체 목록**이고,
실제 전투에서 모두 같은 보상 함수로 들어가는지까지 증명하지는 않는다.
다른 동레벨 무명의 소비자가 존재하지 않는다는 의미가 아니다.

## 시드 분기 근거

원본 `JHAIClient_60014.sb3`의 `getDropByID`, prototype 9:

- PC56 `getCfgByNpc(...).lv` 참조, PC60 `60` 숫자 상수,
  PC61–63 레벨 분기/하한 처리, PC70/72–74
  `'aidrop' + suffix` → `weightRand` CALL.
- PC92/94–96은 색상/클래스 조건으로 진입하는 **두 번째**
  `aidrop` 호출 후보. 일괄적으로 항상 호출한다고 가정하면 안 됨.
- 원본 `JHRandData.weightRand`은 `getRandBetween`을 거쳐
  `Rnds.Sds`에 저장되는 named seed를 소비한다. 장비 옵션용
  `Rnds.Eds`와는 분리된 난수 경로.
- 참고: 구형 산부진 `wild-data.js`는 12레벨 NPC 30233을
  `aidrop1`로 모델링한다. 이는 60 미만 레벨 분기와 정합적이지만,
  만호강의 실제 전투 호출 횟수를 입증하지 않는다.

## 조건부 예측 모델과 한계

`mask-7209-conditional.cjs`는 로컬 게임 세이브의
`Rnds.Sds.aidrop70`을 읽고, 매 전투가 100칸 가중치 표에서
1회 추첨하며 수라가면이 첫 번째 가중치 1일 때의 **후보 회차**를
구한다. 원본 60014 전투 분기, 실제 70레벨 다른 사냥의 간섭,
세이브 이후 활동, 특수 보상 후처리는 추가 검증이 필요하다.
보고용 예측은 결코 확정 드랍이라고 표시하지 않는다.

개인 세이브 및 개인 RNG 값은 연구 브랜치에 저장하지 않는다.
실행 예시: `node research/dungeon-lab/mask-7209-conditional.cjs /local/save.json`.
해당 파일은 로컬에서만 읽고 시드값 자체는 출력하지 않는다.

# 관문 드랍 내부 복원 작업 — 2026-11-25

이 디렉터리는 **연구 브랜치 전용**이며 서비스 페이지나 `main` 브랜치에서 불러오지 않습니다.
실제 사용자 세이브, 시드, 계정 식별자 또는 실측 개인 로그를 저장하지 않습니다.

- 연왕부: 이총관·하상·엽내관·연왕
- 창옥: 무준신·이장·장정
- 벽유교: 독선생·미·불로선인
- 유씨별원: 윤무·고리·이뢰운

문향교·무신전·벽유교 본단은 한국 서버 미출시 상태이므로 이번 연구에서 변경하지 않습니다.

## 이번 복원

`mixed-four-gate.cjs`는 원본 소스 기반 단일 관문 생성기와 특수보상 지급 소비자를
매 회차 연결하여 **한 상태를 이어서** 1~40회 혼합 관문 실행을 계산합니다.

1. `current` / `never_claimed` 가정을 구분하며, 미획득 가정은 **처음 한 번만** 적용합니다.
2. 조건부 지급 결과의 획득 카운터를 다음 회차에 넘깁니다. 획득 내역을 매 회차 0으로 초기화하지 않습니다.
3. 고리의 열쇠 보유·미보유 타임라인을 유씨별원 진입 회차별로 지정할 수 있습니다.
4. 미드랍 시에도 발생한 색상 난수 추첨값을 숨겨진 검증 필드 `rolledGradeCode`에 보존합니다.
5. 원본 세이브를 변경하지 않습니다. 관문 모델이 필드·암시장·장비 옵션용 RNG를 임의로 진행시키지 않도록 검사합니다.
6. 계정 의존 종료 상태는 `includePrivateState`를 명시한 내부 호출에서만 메모리로 반환하며 기본 출력에는 포함하지 않습니다.
7. 공개용 UI 및 배포 버전은 전혀 변경하지 않았습니다.

## 검증 범위

`node research/dungeon-lab/test-mixed-four-gate.cjs`:

- 합성 시작 상태 100종 × 혼합 관문 일정 3종 × 특수보상 상태 2종 = **600건**
- 각 관문 회차의 보스별 장비 ID·색상·숨겨진 색상 추첨, RNG 호출 수, 종료 상태를 독립 회차 호출과 비교
- 기존 외부 시드 레인 및 장비 옵션 시드 유지, 원본 입력 불변
- 가짜 시작 상태의 고리의 열쇠 분기에 따른 후속 RNG 상태 변경
- 벽유교 6회 연속 미획득 가정에서 획득 이력을 매회 초기화할 경우 생기는 **중복 지급 오류**를 독립 재생과 비교
- 인게임 미출시 관문 요청 차단, 미지급/불명 특수 보상 표기 보존

**이것은 내부 모델의 일관성 검증이지, 한국판 미래 인게임 적중을 증명하는 독립 시험이 아닙니다.**

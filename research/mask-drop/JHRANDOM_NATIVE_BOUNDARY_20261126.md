# JHRandom 네이티브·세이브 경계 확인

원본 한국판 60014 `JHExtern_15.sb3` proto8은 `math.jhrandom` 존재 여부를 분기하고, 없을 때 `math.random`을 호출한다. 상위 proto79에서 `math.randomseed(os.time())` 호출을 바이트코드 PC12–17에서 확인했다.

보관된 한국판 60014 `libcocos2dlua.so`의 원문 바이너리 탐색과 동적 심볼 확인에서 `jhrandom`, `JHRandom`이라는 **평문 문자열·등록 심볼은 확인되지 않았다**. `randomseed`는 확인된다. 이 부정 결과는 네이티브가 동적 구성이나 다른 이름으로 함수를 등록할 가능성을 없애는 증거가 아니며, `math.random` 사용이 실게임에서 확정되었다고 주장하지 않는다.

서버4 연속 세이브는 `BattleRnd.S`, `Rnds`(`Sds`, `Rds`, `Eds`, `DefaultRand`)를 보존하지만, 동일한 임의 `JHRandom` 결과의 전체 호출 기록이나 `math` 내부 RNG 상태를 명시적으로 보존한다는 근거는 없다. `BattleRnd`가 곧 `math.jhrandom`이라는 동일성도 원본 증거 없음.

검증된 전투 편성은 `qc_enemy.lua`의 첫 슬롯 산적 1/3 후보. 실제 1회차 0명, 2회차 1명은 이 모델과 모순되지 않으나 **이 2개 관측만으로 3회차 이후 순서를 고정할 수 없다**. 113명 누적 소요 청성산 사냥 339회 평균 역시 독립 균등 추첨 가정하에서만 유효하다.

이 파일은 원본 정적 검증 사실만 보존하며 개인 세이브, 실제 난수, 계정 식별자를 담지 않는다.

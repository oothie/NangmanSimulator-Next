# 수라가면: 청성산 사냥 전후 세이브 비교 방식 (내부 연구 최종안)

## 범위

정확한 산적 등장 회차를 미리 예측하지 않는다. 사용자가 실제로 청성산 70급 일반 사냥을 수행한 뒤 **사냥 전 세이브와 사냥 후 세이브**의 `Rnds.Sds.aidrop70` 변화를 비교한다. 해당 상태 변화를 원본의 추첨 연산(100 범위)으로 재생해 **사이에서 몇 번의 70급 드랍 추첨이 이루어졌을 가능성이 있는지** 역산한다.

그다음 **사냥 후 세이브의 실제 `aidrop70` 상태를 새로운 기준**으로 삼아, 만호강(30681) 수라가면(7209)의 첫 추첨 1/100 당첨 후보 회차를 다시 계산한다. 사냥 횟수와 산적 처치 수를 동일하게 가정하지 않으며, 난수의 진행량을 임의로 생성하지 않는다.

## 입력

1. 청성산 일반 사냥 **전** 세이브
2. 청성산 일반 사냥 **후** 세이브
3. 그 사이 실제로 수행한 청성산 일반 사냥 횟수

가급적 그 사이에 다른 70급 전투나 원보/관문/퀘스트 드랍 관련 활동이 없어야 한다. 해당 구간에서 일어난 별도 난수 소비는 사냥과 구별하지 못한다.

## 계산 단계

1. 양쪽 `aidrop70` 필드의 존재와 형식 확인. 누락 시 계산 중단.
2. 전 세이브의 원시 상태에 100 범위 추첨을 0~1000회 적용하며 후 세이브 상태와 일치하는 진행 횟수 검색.
3. 결과를 일치 1개 / 후보 복수 / 검색 범위에서 일치 없음으로 구분하고, 확인되지 않은 경우 임의로 횟수를 선택하지 않는다.
4. 사냥 후 세이브의 `aidrop70` 상태에서 직접 1% 가설 당첨 후보의 다음 회차와 이후 회차를 계산한다.
5. **1% 가설과 실제 수라가면 지급 분기는 미검증**으로 명시한다. 실게임 아이템 드랍 확정으로 표시하지 않는다.

## 내부 코드

- `compare-qingcheng-saves-mask.cjs`: 핵심 두 세이브 비교 및 다음 후보 회차 갱신
- `qingcheng-save-refresh.cjs`: 로컬 CLI
- `test-compare-qingcheng-saves-mask.cjs`, `test-qingcheng-save-refresh.cjs`: 합성 데이터 기반 테스트

로컬 예시:

```bash
node research/mask-drop/qingcheng-save-refresh.cjs BEFORE.json AFTER.json 2
```

개인 세이브는 프로그램 실행 중 읽기만 한다. 출력은 추첨 진행 횟수 및 후보 회차뿐이고, 실제 난수 상태·계정 정보·세이브 파일 경로는 출력하거나 GitHub에 커밋하지 않는다.

## 현 상태와 검증 범위

**이 워크플로를 최종 구현 방식으로 선택했지만, 수라가면 실제 획득까지 예측되는지는 아직 실측 검증되지 않았다.** 기존에 확인된 드랍 난수 전후 상태의 소비 패턴은 참고 증거일 뿐, 모든 사냥 조건에서 100 범위 추첨 1회라는 보장은 아니다.

청성산 산적 출현용 `JHRandom`의 실행 시각 기반 원시 상태 복원은 이 최종안의 필수 조건이 아니므로 범위에서 제외한다.

공개 시뮬레이터 사이트·버전은 변경하지 않는다.

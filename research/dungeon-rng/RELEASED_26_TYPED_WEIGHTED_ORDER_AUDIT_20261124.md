## 범위와 결과

검사 범위는 출시한 **연왕부(4보스)·창옥(3보스)·벽유교(3보스)·유씨별원(3보스)** 의 일반 장비 발생/색상 테이블 26개뿐이다. 미출시 관문 로직은 변경하지 않았다.

* 원본 60014 SBv3 `TDUP/TSET`에서 복원된 키 **타입, 값, 문자열 끝 공백, 실제 삽입 순서**를 사용.
* 독립 JS 구현 두 개(`Table`, `SourceTable`)의 LuaJIT 2.1 beta3 해시/노드 순회 후보와 기존 원본 복원 Python 레지스트리 순서를 **26/26** 교차 대조.
* 각 테이블의 순회 후보에서 원본 분기 동작 **79개**, 가중치 선택 구간의 가능한 정수 난수 입력 **2,610개**를 전수 검사. 기록된 원본 효과, 연속 구간 시작·끝, 합계, 경계 입력 모두 맞음.
* 원본 명령의 **삽입 순서를 그대로 순회한다고 잘못 가정하는 구현**과 비교하면 26개 테이블 모두 순회 순서가 다름. 같은 정수 난수 입력에서 **장비 여부 1,300/1,300**, **색상 962/1,310**, 합계 **2,262/2,610** 입력에서 분기 키가 다름.
* 연왕(33650)의 색상 합계는 **110**이므로 총합 100으로 정규화하는 예측을 금지. 문자열 `"50 "`과 숫자 `50`은 서로 다른 키로 보존.

위의 2,262/2,610은 **두 알고리즘 가정의 조건부 분기 차이**다. 실제 게임에서 장비가 86.7% 틀린다는 주장이나 이미 실게임 네이티브 `pairs()` 호출 순서가 측정됐다는 뜻이 아니다.

## 최종 검증에 필요한 한 가지

실제 한국판 `libcocos2dlua.so`의 `pairs()`가 생성한 순서를 직접 관측하거나 동등한 네이티브 테스트로 확인해야 한다. Python↔JS 모델 순서가 전부 일치하더라도 같은 해시 모델 가정을 공유할 수 있으므로, 이를 게임 원본 런타임의 독립 검증으로 확대하지 않는다.

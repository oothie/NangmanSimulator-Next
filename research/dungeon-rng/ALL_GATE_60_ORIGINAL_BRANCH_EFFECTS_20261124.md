# 전 관문 60개 원본 RNG 테이블 — 102개 실제 분기 동작 연결 (2026-11-24)

## 구현
- 9개 모드, 보스 30명, 원본 장비 소비자 30개, 장비 여부/색상 생산자 60개 유지.
- 복호화한 5개 원본 SBv3 바이너리(벽유교 35227, 유씨별원 35271, 문향교 50300, 무신전 숙명/절세 이벤트)의 `TDUP/TSET`에서 실제 정수/문자열 키 타입과 삽입 PC를 확보한 **34개 테이블**에 대해 실제 분기 수행 문자열을 추출. **102/102개가 키당 단일 동작**을 가리킴(장비 미드랍 17, 장비 슬롯 추첨 17, 색상 설정 68).
- 원본 코드에서 검증된 키 생성 순서 → LuaJIT beta3 모델의 해시 노드 순회 → 제공된 원본 RNG 출력값에 대한 조건부 분기 → 실제 지급 배열의 장비 ID 및 한국판 이름, 색상 코드까지 통합.
- `source-gated-drop.cjs`의 `evaluateBossWithRolls`는 **RNG 출력값을 입력받는 조건부 매핑**. RNG 전체 호출 순서와 미래 시드를 완성했다고 주장하지 않는다.
- 원본 TDUP/TSET 바이트코드가 **없는 26개 테이블 / 13보스**는 임의의 문자열 키 타입을 부여하지 않고 `blocked` 처리. 대상: 연왕부 8, 창옥 6, 벽유교 본단 기본 6, 추혼 6.

## 원본에서 확인된 2가지 예외

1. 벽유교 **불로선인 35221**: 보상 지급 배열은 장비 9개이지만 현재 검증된 `35227_1.lua` 분기의 장비 슬롯은 `SeedRandom('seed_byj',1,4)`로 1~4번만 선택. 해당 분기에서 5~9번을 유효한 슬롯 후보로 취급하는 것은 오류. 추가 경로의 호출 가능성은 별도.
2. 문향교 **50111**: 장비 여부의 producer 테이블은 `seed_dcy_50111`, 장비 슬롯 추첨은 `seed_wxj_50111`, 색상 테이블은 `seed_wxj_50111`. 원본의 서로 다른 시드 키를 유지; 편의상 `seed_wxj`로 모두 통일하면 안 됨.

보너스 원본 소비자·난수 상태 NPC 구별: 문향교 지급 NPC 50101/난수 NPC 50100, 무신전 절세 지급 NPC 35600/난수 NPC 35603.

# 유씨별원 원본 LuaJIT 해시 방식 — ARM64 바이너리 직접 확인 (2026-11-24)

## 이번에 해결한 문제: SID인지 문자열 내용 해시인지

60014 ARM64 split에서 추출했던 `libcocos2dlua.so`를 **실제 기계어로 교차 검증**했다.

- ELF64 / AArch64, SHA256: `53398b3460ecc678d8be1ad62b8afd89e370d7ca7a77d65396c00c0706443154`
- LuaJIT 버전 문자열 참조 위치: 코드 `0x82ea0c` → 데이터 `0xf106d4`, `LuaJIT 2.1.0-beta3`
- 문자열 인턴 함수 시작 `0x7e3a24`는 입력 문자열 바이트로 32비트 해시를 계산: `0x7e3a70`(원문 로드), `0x7e3a78`(회전 혼합), `0x7e3ad8`(마지막 혼합).
- `0x7e3bbc: stp w25, w20, [x0,#0xc]`는 문자열 객체 `GCstr`의 offset +0x0c에 계산된 **내용 해시**, +0x10에 길이를 기록한다.
- 첫 번째 VM 조회 `0x803104`–`0x80311c`에서 `GCtab.hmask`(offset +0x34), `GCstr.hash`(offset +0x0c), `GCtab.node`(offset +0x28)를 읽고 **bitwise AND**, 노드 인덱스 × 24바이트로 위치를 결정한다.
- 두 번째 독립 VM 조회 `0x8053dc`–`0x8053f4`에서도 동일 해시 마스크·문자열 내용 해시·24바이트 노드 계산을 확인했다.

**결론: 이 60014 ARM64 게임 바이너리의 두 조회 경로는 문자열 SID가 아니라 문자열 내용 기반 해시를 실제 사용한다.** 버전 문자열만으로 내린 추정이 아니며, 소스의 `hashstr(t,s)=hashmask(t,s->hash)`와 네이티브 기계어가 부합한다.

## 자동 검사

`node research/dungeon-rng/native-arm64-hash-audit.cjs /path/to/libcocos2dlua.so`

SHA 및 16개 AArch64 기계어 지문을 검증한다. 원본 라이브러리나 사용자 세이브는 이 공개 연구 브랜치에 포함하지 않는다. 로컬에서 해당 원본에 대해 검증 성공하고, 별도 Python 검증 스크립트에서 정상 5개 테스트(변형 명령어 감지 포함)를 통과했다.

## 기존 유씨별원 과거 RNG 조건부 재생의 의미

기존 19/19 시드 전이, 장비 발생/인덱스 3/3, 과거 재료 A/B/C 및 3보스 색상 코드 6/6 조건부 재생은 유지된다. 숫자 키 `201`과 문자열 `'200   '` 구분, TDUP 메타 키 `key`, 초기 해시 할당 수와 재해시 규칙을 사용하되, 한 관문 기록에 맞는 조건부 재생과 미래 독립 예측은 구분한다.

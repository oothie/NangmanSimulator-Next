# 유씨별원 LuaJIT 테이블 복원 감사 — 2026-11-24

## 원본 추출 자료와 범위
기존 비공개/Library 아카이브의 복호화된 `35271_1.lua.multidec.sbc`와 `35271_1.lua.weight_key_construction.json`을 재조회했다. 실제 업로드 Whale의 게임 버전은 독립 확정되지 않았으며, 코드가 배포 60014 런타임과 바이트 단위로 동일하다는 의미도 아니다.

- SeedKeyRoll의 TDUP 상수 10개는 모두 `{key='seed_lsby'}` 한 해시 항목, 배열 항목 0개를 가진다.
- 원본 `lj_bcread_ktab`는 `nhash=1`을 `hsize2hbits(1)=1`로 변환하며, 표준 LuaJIT는 초기 해시 2개 노드로 생성한다.
- PC 503 TDUP 다음 507/511/515/519/523의 재료 C 실제 키는 각각 정수 `201`, 문자열 `'200  '`, `'200   '`, `'200    '`, `'200     '`이다.
- 표준 2.1.0-beta3 소스의 문자열 내용 해시, IEEE754 숫자키 `hashrot`, Brent 방식 충돌 재배치, 재해시 노드 순서를 이용하면 재료 C 난수 820/1001에 대해 `'200   '`을 선택해 원본 지급 ID `3030`에 도달한다.
- 같은 초기 hash bits=1 가정과 추출 순서를 이용하면 재료 A: `2601`, B: `8803`, C: `3030`, 윤무/고리/이뢰운 색상 코드: `2/2/2` 등 과거 6/6 기록과 일치한다. 원래 v15 연구에서 이미 같은 조건부 일치가 기록되었으며, 이번 결과는 독립 소스 재검토·회귀 보강이지 새로운 실게임 홀드아웃 예측이 아니다.

## 미확정
`LuaJIT 2.1.0-beta3`라는 ELF 버전 문자열만으로 게임 네이티브가 2017년 내용 해시 방식인지, 이후 문자열 SID 방식이 혼합된 포크인지 증명되지 않는다. 문자열 SID는 최신 LuaJIT 일부 소스에 존재하지만, 2017년 beta3 원본 `GCstr`/테이블에서는 문자열 내용 해시가 사용된다.

`JHTaskFile` 생성자 경로/TDUP 실행 여부, 원본 C 라이브러리의 실제 `lj_str_new`/테이블 구현, 실게임 독립 미래 드랍 비교가 추가로 필요하다. 따라서 색상 코드 2가 녹색이라는 과거 대응 및 유씨별원 장비 발생 일치는 **기존 사례 조건부 재현**이며 실제 관문 미래 드랍 ID·색상 확정 배포를 승인하지 않는다.

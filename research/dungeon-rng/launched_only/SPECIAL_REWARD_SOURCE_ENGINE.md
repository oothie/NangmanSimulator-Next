# 출시 4관문 특수 보상 연구 엔진

배포 사이트와 분리된 원본 지급자 검증 코드이며 실제 사용자 세이브나 실측값은 포함하지 않는다.

## 원본 범위

- 보존된 보상 소비자 15개에서 특수보상 지급 규칙 40건 추출. 이 중 연왕부·창옥·벽유교 12개 SBC는 54506 추출본이고 유씨별원 3개는 별도 Whale에서 복원된 자료다. 현재 한국판 60014와 전체 함수 동등성은 미검증.
- 연왕부 12건, 창옥 12건, 벽유교 9건, 유씨별원 7건.
- 최초 1회 제한 24건, 잔편 10·15개 제한 11건, 횟수 제한이 없는 조건 4건, 임시 범위 확인 필요 1건.
- 지급 플래그 2에서 1로 돌아가는 원본 조건부 복구 37건. 이를 매 회차 무조건 실행하지 않는다.
- 특수 아이템 ID 35종을 한국판 이름으로 식별해 단순 '특수 보상' 표시를 제거.

## 실행 시나리오

- current: 세이브에 기록된 원본 지급 횟수를 유지한다.
- unclaimed: 특수 보상 획득 횟수만 0으로 가정하며 RNG·재료 상한·임무 상태는 변경하지 않는다.
- fresh: 보상 횟수와 이전 지급 플래그를 가상 초기화한다. 실제 미획득 시점의 모든 게임 상태를 복원한다는 뜻은 아니다.
- 유씨별원 열쇠 실제 보유 여부는 과거 누적 획득 기록과 구분한다.
- 임시 범위 GetP 조건을 저장 파일에서 증명할 수 없으면 지급 확정으로 표시하지 않는다.

## 사용

node research/dungeon-rng/launched_only/test_special_reward_source_engine.mjs
node research/dungeon-rng/launched_only/test_special_reward_four_gates.mjs
node research/dungeon-rng/launched_only/special_reward_lab_cli.mjs --save /private/local-save.json --gate 창옥 --clears 10 --mode current
node research/dungeon-rng/launched_only/special_reward_lab_cli.mjs --save /private/local-save.json --gate 창옥 --clears 10 --mode unclaimed

개인 세이브는 로컬 파일로만 읽으며 공개 저장소에는 올리지 않는다. 배포 사이트·버전은 그대로 유지한다.

## 아직 미확정

- 과거 획득 후 진행된 임무·최초 입장 상태를 현재 세이브만으로 모두 복원할 수 없다.
- 벽유교 귀용문 개방·고리의 열쇠 사용·임시 범위 보상은 별도 원본 조건 검증이 필요하다.
- 장비·재료 RNG와 보상 소비자는 분리되어 있으며 모든 LuaJIT 실행 경로를 네이티브로 검증한 상태는 아니다.
- 유씨별원 소비자 보존본과 다른 3관문의 원본 버전 동일성은 추가 확인이 필요하다.

## 회차별 원본 생성-지급 연동 개선

- 관문 생성기 4개 모두 다음 회차 시드·누적 변수 상태를 연구용 반환값으로 제공한다. 실제 사이트 엔진 파일은 수정하지 않았다.
- forecastInterleavedSpecials는 1회 추첨, 원본 지급 카운터 증가, 드랍 플래그 후처리, 다음 회차 진입을 순서대로 처리한다.
- 특정 보상 ID를 지정해 1~2000회 범위에서 최초 지급 성공 시 탐색을 중단할 수 있다.
- GetP의 temp 범위는 globalVariable과 분리해 이어가며 미확정인 경우 당첨을 지급으로 확정하지 않는다.
- 창옥 무준신 몰우전은 54506 V174 SBC에서 지급 후 플래그가 0으로 복원됨을 확인해 일반 보상의 2 처리에서 분리했다.
- 54506 V174 지급 규칙 33개에서 실제 후처리 명령을 대조했다. 카운터 SetP 10건·AddP 21건·카운터 미변경 2건, lost 복구 31건을 확인했다. 유일한 지급 후 플래그 0 예외는 몰우전이며, 유씨별원 Whale 7건의 같은 작업은 아직 필요하다.
- 54506 원본 스크립트 8개에서 잔편 지급 명령 후 GetP == 14 또는 9가 되는 시점에 buyshop 상태를 증가시키는 8종 조건을 추출했다. 따라서 15·10개째가 아닌 14·9개째 지급에서 후속 해금이 발생하도록 교정했다. 바이트코드 실행 순서는 추가 네이티브 검증 대상이다.
- 벽유교 불로선인의 귀용문 열쇠 지급에 GetP(3970) == 0이라는 별도 숫자형 가드가 있는 것을 확인했다. 이는 get_3970 기록과 다른 상태이므로 미확정이면 지급을 확정하지 않는다.
- 패배(lost) 이벤트에만 적용하는 원본 지급 취소 함수를 별도 구현했다. 단순 연속 클리어에 임의의 패배 처리를 삽입하지 않는다.

- test_special_reward_interleaved.mjs: 7개 순차 상태 피드백·장기 탐색·열쇠 분기 검사.

## 배포 전 남은 기준

- 원본 게임의 모든 보스별 분기·LuaJIT 가중치 순회가 복수 입력 상태에서 네이티브와 완전히 일치하는지 검증 필요.
- 원본 Whale 유씨별원 7개 소비자의 지급 후 상태와 패배·퇴장 복구 이벤트 진입 조건 검증 필요.
- 임무 해금 상태 변화, 일부 보상 임시 변수, 최초 입장 상태 및 중간 전투 실패까지 실제 연속 게임 진행과 비교 필요.
- 이 조건들을 완료하기 전에는 사이트에 확정 엔진으로 이식하지 않는다.

## 이번 추가 확인: 54506 소비자 원본과 60014 이름 분리

- 54506 보스 이벤트 원시 SBC 33건의 AddBattleDrop 뒤 지급 조건식이 보존된 추출 레지스트리와 모두 일치함을 독립 점검. 유일한 추가 숫자형 GetP 조건은 벽유교 불로선인 GetP(3970)==0이다.
- 한국판 60014 V6.20 아이템 표에 등장하는 특수보상 35종의 명칭을 전수 대조. 이는 이름의 일치이며 보상 함수 자체의 버전 동등성 증명이 아니다.
- 40개 소비자 규칙에 54506-original 33건/Whale-recovered 7건 출처와 native60014Parity=unverified를 지정했다.
- 보존된 원본 레지스트리의 quantity 필드는 AddBattleDrop 세 번째 인수를 잘못 명명한 역사적 필드다. 장비 일반 드랍 원본에서 같은 자리에 GetP(drop_*_color)가 오는 점으로 이를 색상 등급 인수로 해석한다. 연구 엔진 출력은 지급 수량 1개, 등급 코드를 별도 필드로 나눈다. 원본 레지스트리의 숫자는 추출 증거 보존을 위해 변경하지 않는다.
- V174 파생 원본은 1.124.54506이고 60014 자료에는 해당 스토리 보스 SBC 원본이 보존되어 있지 않다. 따라서 원본 시드·보상 로직 전부 동일하다는 결론은 내리지 않는다.

## 장기 재생 안전 기준

- 가상 세이브에서 2,000회씩 재생한 결과 연왕부·창옥·벽유교는 요청 범위까지 실행됐다. 벽유교는 숫자형 GetP(3970) 미확정 시 보상 지급을 미확정으로 표시한다.
- 유씨별원은 원본 기반 재료 A 테이블의 모든 후보가 소진되는 가상 상황에서 980회까지 재생되고 981회부터 원본 가중치가 0이 된다.
- 해당 소진 지점 이후의 시드나 보상은 임의로 생성하지 않고 incomplete=true, stoppedAt=981을 반환한다. 이 경계는 해당 가상 초기 상태의 결과이며 모든 실제 계정의 상한이라고 단정하지 않는다.

## 유씨별원 35271_1 생산자 전수 검사 및 Whale 소비자 분리

- 원본 35271_1.lua.reconstructed.json의 단계 5는 윤무 5020 확률 보상 조건, 단계 6은 조건 없는 SetP('drop_35260_rarematerial',1), 단계 7은 seed_lsby를 소비하는 장비 여부/슬롯 분기다.
- 35271_1의 원본 플래그 문자열과 유씨별원 소비자 7건의 드랍 플래그를 비교해 **7/7 모두 존재**함을 확인했다. 기존 생산자 연구 코드에는 단계 6이 누락되어 8801 연금니 보상 소비자에 추첨이 전달되지 않았다.
- 단계 6을 원본 순서에 복원했다. RNG 호출이 없는 SetP이므로 장비 슬롯·색상 시드에 새 난수 호출을 추가하지 않는다.
- 8801 보상 소비자의 조건은 GetP('drop_35260_rarematerial') ~= 0 and GetP('get_8801','temp') == 0이다. 소스가 확인하지 않은 temp 상태를 현재 save.globalVariable과 동일시하지 않는다.
- temp가 제시되지 않으면 지급 미확정이며, 한번 제시된 temp 값도 다음 클리어까지 유지된다는 원본 증거가 없으므로 기본 tempLifetime=unknown에서 다음 회차는 미확정으로 되돌린다. 유지(persist)와 초기화(reset)는 명시적으로 선택한 비교 가정에 한한다.
- 유씨별원 복구 분기 6건은 Whale 추출 레지스트리로 조건 자체는 확인되나, 이를 원본 54506과 같은 lost 이벤트에서 실행한다는 독립 증거가 없다. 따라서 applyOriginalBattleLoss 기본 경로에서는 적용하지 않고, 옵션 includeUnverifiedWhaleRollback=true로만 가상 실험한다.
- 고리의 열쇠 get_8915 증가는 롤백의 -1 명령만으로 순방향 +1을 확정하지 못하므로 원본 검증 전 영수증 카운터를 자동 변경하지 않는다. 가설 모드에서만 시험 가능하다.
- 원본 60014 지급 함수 완전 동등성은 계속 미검증. 사이트 이식 금지 상태 유지.

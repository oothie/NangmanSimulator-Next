# 1123 입장 전 → 1124 실제 장비 생성 순서 검증 (2026-11-24)

## 검사 기준
기존 v30 실험 엔진은 1123(입장전) 세이브를 입력으로 각 관문 원본 소스의 난수 분기와 장비 슬롯·색상을 예측했다. 본 보고서는 **기존 예측을 수정하지 않고**, 1124 실제 종료 세이브의 `Equips`를 `OnlyID` 생성순으로 정렬해 장비 ID/색상을 교차 검사한 결과다. 유저 세이브 내용, 계정 식별자, 장비 개별 OnlyID, 실제 RNG 시드 값은 공개하지 않는다.

### 90급 일반 장비 생성순서
두 세이브 사이 90급 일반 장비 16개가 새로 생성됐다. 구간마다 `OnlyID`는 연속적이며, 세 가지 관문의 원본 가설 예측과 다음과 같이 일치한다.

| 대상 | 원본 엔진 예측 | 실제 생성 장비 | 판정 |
|---|---|---|---|
| 벽유교 (분기 37) | 청운반지 녹색(5409), 흑살곤 청색(4609) | 새 장비 목록 연속 시작 2개 동일 | **2/2** |
| 창옥 | 자미아대 청색(5009) | 그 다음 생성 장비 동일 | **1/1** |
| 유씨별원 1회 | 자미아대 녹색(5009), 오잠보갑 백색(5209) | 16개 목록에서 유일하게 나타나는 연속 7개 구간의 첫 2개 | **2/2** |
| 유씨별원 2회 | 자미아대 자색(5009), 지수검 백색(4209) | 같은 구간 중간 2개 | **2/2** |
| 유씨별원 3회 | 자미아대 녹색(5009), 청운추 백색(5609), 수라장갑 청색(4009) | 같은 구간 마지막 3개 | **3/3** |

검증 범위 합계 **10개 장비 ID/색상/생성 순서 일치**. 보스별 미드랍은 다른 소스 로그로 직접 검증되지 않았으므로 이 합계에 넣지 않았다.

### 원본 시드 전이 대조
- 유씨별원 `win_lsby` 3 증가. 이전 v30이 예측한 3회 후 `seed_lsby`는 1124의 실제 종료 시드와 동일.
- 벽유교 `win_byj` 1 증가. **분기37 적용=True**인 v30 시뮬레이션의 종료 `seed_byj` 일치. 미적용=False 분기는 불일치.
- 창옥 `win_dcy` 1 증가. `seed_dcy_40372/40373/40374` **3/3** 일치.
- 연왕부 `win_ywf` 1 증가. 기존 v30 종료 `seed_33650/33652/33653/33654` **0/4** 일치. 이 관문은 현재 모델을 정확 예측이라고 표시할 수 없다.
- 이 저장 사이 `win_lishan, win_overlord, win_tomb`도 증가했다. 따라서 전체 장비 16개 중 일치한 구간 이외의 나머지는 원본 관문만의 보상이라고 임의로 분류하지 않는다.

### 중요한 검증 한계
1. `Equips` 변경과 `OnlyID`의 순서는 실제 새 장비 생성의 강력한 증거지만 개별 장비의 **보스 지급 출처가 직접 기록된 로그**는 아니다. 본 판정은 생성 순서와 원본 RNG 슬롯 모델, 시드 종료값을 함께 교차 확인한 결과다.
2. v30의 일부 장비 후보 배열, 보상 순서 가설에 오류가 남아 있고 특히 연왕부에서 종료 시드 0/4 불일치다. 전 관문 예측 완성을 주장하지 않는다.
3. 새 모델의 300개 혼합키 테스트는 Python/JavaScript 소스 기반 모델의 동등성 검사다. 실제 원본 ARM64 런타임 300회 실행 결과가 아니다.

## 코드
- `luajit-beta3-hash-strict.cjs`: 정수 배열 영역 + 문자열 내용 해시 + 노드 재배치/재해시 모델
- `luajit-beta3-hash-strict.test.cjs`: 원본 16 테이블 및 배열 영역 고정 회귀
- `luajit-beta3-hash-property.test.cjs`: Python 기반 300개의 결정적 혼합키 출력 SHA256 교차검증
- `liu-three-clear-holdout.cjs`: **사용자가 직접 로컬에서 제공하는** 전후 세이브와 기존 예측으로 장비 연속 일치 검증. 파일 내용은 외부로 보내지 않음.

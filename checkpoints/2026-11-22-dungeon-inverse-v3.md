## 추가 역검증: 공통 품질 가중치 *순서*가 실제 색상 차이를 설명
- `seed_byj` 수정된 호출 순서의 품질 추첨값 99/62/64는 각각 청색(3)/백색(1)/백색(1). `seed_dcy_40373` 수정된 재료 범위의 품질 추첨값 22는 녹색(2).
- 품질 가중치 숫자 `white=50,green=30,blue=15,purple=5` 자체를 고정하고 4! = 24가지 구간 순서를 전수 탐색하면 실측 4개 모두 만족하는 배열은 세 가지:
  1. `[green,white,purple,blue]` = `[2,1,4,3]`
  2. `[green,purple,white,blue]` = `[2,4,1,3]`
  3. `[purple,green,white,blue]` = `[4,2,1,3]`
- 기존 산부진 `[white,purple,blue,green]`, yy-sim 표시 데이터 `[white,green,blue,purple]`는 어느 것도 4개를 재현하지 못함.
- 예시 후보 `[2,1,4,3]`를 적용하면 벽유교 3보스 + 창옥 3보스의 아이템 번호/등급 **6/6**, 관련 시드 4/4 복원. 다만 동일 세이브 실측에 맞춘 **사후 적합**이며 미래 검증/3후보 구별 전까지 확정 알고리즘이 아님.
- 3개 색상 배열 후보를 구별하기 위해서는 현재 후보들이 서로 다른 값을 출력하는 품질 추첨값을 가진 별도의 실측이 필요.
- 유씨별원은 재료 3회 선택 테이블과 이뢰운 재료 분기 판정이 여전히 어긋남. 산부진 `name_drop_a` 가중치 `[6,3,8,5,2,11,1,7,4,9,10]`는 1..11의 순열로서 추첨 가중치가 아니라 테이블 인덱스를 잘못 해석했을 가능성이 높음. 단일 기존 추첨 범위 하나만 1..500000으로 치환하는 검색으로는 최종 시드에 도달하지 못함. 복수 재료 테이블 재구성 필요.

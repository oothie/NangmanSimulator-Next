## v1.0.5 작업
- `vendor/sanbujin/drops/dungeon-v2-audit.js` 독립 v2 소스/원본 추적 엔진 추가.
- `source`: DAILY_DATA의 보스별 skr 보상 가중치와 uniq 후보 호출을 독립적으로 재생. 자료에 없는 스토리 게이트·재료 RNG 소비는 가설로 명시. 창옥은 일반 장비 미드랍이면 색상 RNG가 호출되지 않도록 구분.
- `native`: 복원 산부진 함수를 직접 실행하고 난수 키·진입 시드·범위·추첨값·진행 후 시드를 기록. 실행 불가 시 미복원 표시, 기존처럼 임의 일반 드랍으로 대체하지 않음.
- 반복 관문별 win 카운터를 진행하고 같은 키의 시드가 2/3회차에 유지 누적됨. 입력 세이브는 읽기 전용.
- 사용자 실측은 `fixture`로 진단 비교에만 사용. 1122 실제 시드를 공개 repo에 저장하지 않음.
- 사이트 UI에는 기본 예측은 유지하고 '신규 RNG 엔진 v2 · 별도 계산 결과 확인 (검증 중)'에만 노출.
- `tests/dungeon-v2-audit-smoke.cjs`로 9보스 fixture, 난수 기록 불변성, 반복 시드 누적 검사.

## 반드시 해결할 항목
1. yy-sim DAILY_DATA는 확률/보상 **표시용 데이터**이며 네이티브 실제 보상 호출 순서가 완전하지 않다. 특수 보상·재료·임무 게이트·미드랍 시 색상 RNG 처리를 원본 게임/APK 함수와 비교해야 한다.
2. 기존 Whale LCG JS 재구성 `SBJWildDrop.draw`가 원본 yy-sim WASM `int_rand`와 일치하는지 별도 검증이 필요하다. 함수 이름이 같아도 인수/반환값 의미가 다를 수 있다.
3. 산부진 데이터는 실제 장비 후보 풀과 원본 NPC별 예외를 따로 검증해야 한다. 실측에서는 이장 4009, 이뢰운 4209가 발생했으나 기존 산부진 후보 풀과 원본 경로가 불일치했다.
4. 1122 세이브와 1회 진행 후의 **세이브 간 난수 시드 변화**를 보스별로 확보하면 누락 호출 횟수와 키를 역산 가능하다. 결과 기록만으로 난수 소비의 모든 원인을 특정할 수 없다.
5. 실측값을 강제로 반환하거나 1122 시드만 맞추는 보정은 금지. 엔진 전체에서 재현 가능한 함수를 복원해야 한다.
